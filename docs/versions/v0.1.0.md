# PropOS v0.1.0 — Release Notes

Status of each capability in the v0.1.0 spec (`docs/versions/PropOS v0.1.0.pdf`,
local only) after the completion work. "Done" = end-to-end reachable by a user in
the UI today; "Partial" = some flows of the feature are missing a surface;
"Config" = shipped but requires environment/credential setup to activate.

> **Verified 2026-07-02** against the code at `201e586` (audit R2). Percentages
> are DONE + 0.5×PARTIAL over the spec bullets for that feature, excluding the
> explicitly deferred ones. An earlier revision of this file marked F2/F3/F7 as
> "Done"; that was optimistic and is corrected below — the gaps are UI surfaces,
> not backend endpoints.

## Required environment variables (new in v0.1.0)

| Variable | Where | Purpose |
|----------|-------|---------|
| `VITE_VAPID_PUBLIC_KEY` | frontend (Vercel, both projects) | Web-push subscription. Backend already holds the private key. |
| `INTERNAL_JOBS_SECRET` | backend (Cloud Run) | Auth for Cloud Scheduler → `/internal/jobs/*`. |
| `EMAIL_SYNC_ENABLED` | backend | Toggle IMAP email sync. |
| `EMAIL_IMAP_HOST/PORT/USER/PASSWORD` | backend (secrets) | Titan mailbox credentials. |
| `EMAIL_SYNC_TENANT_ID` | backend | Tenant that owns the synced mailbox. |

See `docs/cron-jobs.md` for the Cloud Scheduler setup (reminders + email sync).

## Cron jobs

Two Cloud Scheduler jobs (5-min cadence) hit internal endpoints:
- `run-due-reminders` — push reminders for events/tasks/payments.
- `email-sync` — IMAP poll → portal-lead threading into CRM.

**Neither job exists in the project yet** — the endpoints are live, the schedulers
were never created. A third job (`refresh-analytics`) is still missing its
endpoint, so the CRM/finance materialized views only refresh on a manual button
press. See `docs/cron-jobs.md`.

## Not yet operational in production

Code-complete but switched off, because the secrets were never injected into
Cloud Run (`config/docker/cloudbuild.yaml` ships 7 secrets: supabase ×3, vapid ×2,
cerebras, groq):

| Capability | Blocked by |
|---|---|
| WhatsApp in/out (Propo + Client Agent) | `kapso-api-key`, `kapso-webhook-secret`, `kapso-phone-number-id` |
| All outbound email | `resend-api-key`, `resend-from-email` |
| Reminders + email sync cron | `internal-jobs-secret` + the two Scheduler jobs |
| Portal-lead ingestion | `EMAIL_SYNC_*` (Titan IMAP) |
| Agent env in prod | `cloudrun-env.yaml` still defines `ANITA_*`; the backend reads `AGENT_*`, so prod runs on defaults |

## Explicitly NOT in v0.1.0

- Portal publishing APIs (F6 is content package + manual posting).
- LLM provider abstraction — **Groq-only** (Cerebras/Anthropic swap deferred).
- Web Speech API (audio is MediaRecorder → Groq Whisper).
- Calendar recurrence; WhatsApp reminder channel (enum reserved, not delivered).
- Multi-account / per-tenant IMAP creds; IMAP APPEND to Sent; HTML email render (text-only).
- Auto-opportunity creation from portal leads (sync creates the contact and the email thread only — no interaction row either, despite what earlier notes claimed).
- Receipt OCR; bank reconciliation.
- Generic data-table browser; AI update_property / complete_task / delete_record.
- Property photo-edit pipeline (upload via WhatsApp agent works; in-app editor deferred).

## Security note

P0 closed a real hole: the conversational agent (`/v1/agent/*`) and proposal
acceptance (`/v1/pending/*`) were callable by **any** authenticated tenant user.
They are now `require_role`-gated. CRM/finance routers are role-gated too.

Still open at v0.1.0 (tracked in the private audit reports, see
`docs/audits/README.md`): CRM/finance routers check the role but not the
per-admin scope; the backend runs as service-role so RLS is not a backstop; and
owner/buyer document access is filtered in Python rather than against
`property_grants`. **Do not load real customer data until these close.**
